# Build the island as layout, not decoration

Sahaj should build the site as a **statically rendered HTML document whose layout drives a cheap 2D signed-distance-field (SDF) shader**. The black pill is a WebGL2 fragment shader that merges rounded boxes with a smooth-minimum (`smin`) function, and it springs toward the rectangles of invisible DOM "slot" elements, so every word stays real, accessible HTML. The signature moment, where the island dissolves into code-token particles that form his portrait, should be a **lazy-loaded, scroll-reversible GPU particle effect** built on three.js `three/webgpu` + TSL, which falls back to WebGL2 automatically. The concept is defensible as original. Dynamic Island nav pills are now commodity Framer and shadcn components, and Liquid Glass SDF blobs are everywhere, but the research turned up **no award-winning portfolio where the entire site is a GPU metaball pill**. It also turned up no published demo that uses a site's own source tokens as particle glyphs. Award juries reward exactly this combination of deep GPU work and easy navigation (Igloo Inc, 2024 Site of the Year). Recruiters and hiring managers punish the failure mode just as clearly: slow loads, a frozen canvas, and content gated behind an intro. So the build has to be HTML-first. Name, role, flagship projects and resume links must render before any WebGL loads, and the "wow" must run as an enhancement that survives a mid-range Android phone. Done that way, the site doubles as a case study for FLOAT, his real Windows Dynamic Island, which turns the visual gimmick into evidence of systems taste.

## Thirteen reference sites teach restraint, DOM sync, and custom tooling

The top tier of WebGL web design is studio work, and its lesson is integration rather than spectacle. **Lusion v3 won Awwwards Site of the Year and Developer Site of the Year 2023**. The jury singled out how its clean interface "blends seamlessly" with over-the-top animation ([Awwwards SOTY 2023](https://awwwards.com/annual-awards-2023/site-of-the-year)), and its pointer-driven fluid is a cursor response layered over readable UI ([Awwwards](https://www.awwwards.com/inspiration/accelerated-webgl-fluid-simulation)). **Igloo Inc by Abeto took both titles in 2024** for combining "an immersive 3D experience with an easy to navigate, scroll interaction" ([Awwwards SOTY 2024](https://www.awwwards.com/annual-awards-2024/site-of-the-year)). Its case study credits custom tooling, a volume data exporter and an "expansive fluid simulation", for its depth ([Awwwards case study](https://awwwards.com/igloo-inc-case-study.html)). Igloo is the formula to borrow: wild GPU work, plain scroll navigation, and a visible engineering pipeline.

Among solo developers the bar looks different. **Bruno Simon's folio-2025 won Site of the Month in January 2026** ([Awwwards](https://www.awwwards.com/websites/winner_category_portfolio/)). It proves that one strong interaction metaphor (his drivable car, Sahaj's pill) can carry a whole site, and that open-sourcing the code adds credibility ([CreativeDevJobs](https://www.creativedevjobs.com/blog/best-threejs-portfolio-examples-2025)). **Samsy's Gen-02 earned SOTD plus the Developer Award in October 2025** with custom WebGPU rendering ([webgpu.com](https://www.webgpu.com/showcase/gen-02-portfolio-an-immersive-world/)), which shows WebGPU is now an award-level differentiator. Roman Jean-Elie's Portfolio '25 (SOTD) matters most mechanically. Its Codrops making-of describes **tracking DOM element bounds and mapping them to WebGL coordinates** ([Codrops](https://tympanus.net/codrops/2025/11/27/letting-the-creative-process-shape-a-webgl-portfolio/)), and that is the exact technique a morphing pill needs. Arnaud Rocca's 2026 site pairs GSAP with OGL, a lightweight alternative to three.js for single-shader scenes ([Codrops](https://tympanus.net/codrops/2026/03/31/arnaud-roccas-portfolio-from-a-gsap-powered-motion-system-to-fluid-webgl/)). Stefan Vitasović's transitions read as one continuous object ([Codrops](https://tympanus.net/codrops/2025/03/05/case-study-stefan-vitasovic-portfolio-2025/)), the same goal as a pill that never unmounts.

Several winners show that the Developer Award comes from motion polish rather than raw 3D. They include Antoine Wodniack (SOTD December 2024), Gianluca Gradogna (SOTD January 2025, with scroll mechanics only) and Jesper Landberg (SOTD September 2026, the most recent benchmark) ([Awwwards portfolio winners](https://www.awwwards.com/websites/winner_category_portfolio/)). Juror Hon Tran cites Minh Pham as proof that "WebGL can stay tasteful", with 3D framing the work instead of competing with it ([Hon Tran](https://www.hontran.dev/blog/best-award-winning-websites-2026)). Two sites model performance discipline. Weisdevice throttles raycasting to 30 FPS and pauses its render loop on project pages, and Jordan Breton (FWA SOTD) uses fixed, authored camera stops instead of free roam ([CreativeDevJobs](https://www.creativedevjobs.com/blog/best-threejs-portfolio-examples-2025)). For the particle moment, the closest commercial precedent is **Shopify Editions Spring 2026's particle-dispersing type with scroll sequencing** ([Utsubo](https://www.utsubo.com/blog/best-threejs-websites-2026)).

Differentiation is the harder problem, because the pill alone is not novel. Framer sells a "Dynamic Island Nav" with spring physics, keyboard navigation and reduced-motion support ([Framer](https://www.framer.com/marketplace/components/dynamic-island-nav/)), plus a whole "Folioos" portfolio template whose island label changes per section ([Framer](https://www.framer.com/marketplace/templates/folioos/)). Aceternity and 21st.dev ship React versions ([Aceternity](https://ui.aceternity.com/blocks/illustrations/dynamic-island)), and Liquid Glass Studio already does SDF shape-merging with refraction in WebGL2/WebGPU ([builtatlightspeed](https://www.builtatlightspeed.com/theme/iyinchao-liquid-glass-studio)). Sahaj's site must differ on four axes at once. **The pill is the only UI surface, and its morphs replace page layout.** The material is **matte or glossy black metaball rather than refractive glass**, which avoids reading as a Liquid Glass clone. Cursor gravity is physically modeled with springs. And the code-to-portrait dissolve is a signature no template offers. Framer's keyboard and reduced-motion support also sets the minimum accessibility baseline the WebGL version must match. Two caveats apply: Codrops pages returned HTTP 403 to the researchers, so those case studies were read only through search summaries, and absence of a prior "Dynamic Island SDF portfolio" in search results is not proof that none exists.

## A 2D SDF shader costs roughly one-sixtieth of a raymarcher

The island should be a 2D fragment shader, not a 3D raymarch. Each layout state is a set of up to eight rounded boxes from Inigo Quilez's exact `sdRoundedBox`, which takes four independent corner radii. They are merged with his **normalized quadratic `smin`, in which `k` equals the blend thickness in pixels** and also the bounding-box expansion needed to contain the blend ([IQ, 2D distance functions](https://iquilezles.org/articles/distfunctions2d/); [IQ, smooth minimum](https://iquilezles.org/articles/smin/)). IQ defaults to the quadratic form himself because it is "fast, close enough to circular, never overestimates." The catch is that quadratic `smin` is **not associative**: blend order changes the shape slightly, so the shape order must stay stable across states. Exponential `smin` is order-independent but distorts shapes everywhere ([IQ](https://iquilezles.org/articles/smin/)). The cost argument is decisive. A 2D SDF costs about N_shapes evaluations per pixel, while a raymarcher costs 32–96 steps times N_shapes plus extra evaluations for normals. For six shapes at 64 steps that is **roughly 60–70 times the ALU work** (an estimate from the research notes, not a benchmark). The Codrops droplet-metaball tutorial raymarches spheres along the mouse trail ([Codrops](https://tympanus.net/codrops/2025/06/09/how-to-create-interactive-droplet-like-metaballs-with-three-js-and-glsl/)). It is the right reference for cursor-trail elasticity but the wrong architecture for persistent UI chrome.

The material should be "2.5D". Derive a fake height from the distance, with a squircle bezel profile `y = pow(1 - pow(1-x, 4), 1/4)` that reads as a thin, smooth lip ([kube.io](https://kube.io/blog/liquid-glass-css-svg/)). Build a normal from the SDF gradient, then add a Fresnel rim, a tight specular highlight and an inner shadow. This is where the brand lives. IQ's mix-factor `smin` variant returns a blend weight alongside the distance ([IQ](https://iquilezles.org/articles/smin/)). That weight can tint merge seams, Fresnel rims and timeline nodes along the **violet `#7c5cff` to cyan `#00d4ff`** ramp while the body stays black, so the accent appears exactly where liquid is happening. Refraction is mostly invisible on a black pill over a near-black background, so skip it. Anti-aliasing uses `fwidth(d)` with a `smoothstep` across about one pixel, which stays robust near `smin` seams where the field is not an exact distance.

Morphs come from **springing shape parameters, not lerping fields**. Each state's center, half-size and corner radii are read from invisible slot elements laid out by ordinary CSS grid and flex. The shader's uniforms (a `vec4` array of up to eight entries) spring toward those targets, and `smin` melts them together. Splitting the pill into blobs means starting with coincident shapes and pulling them apart. The neck stretches and pinches off once the gap exceeds about 2k, and an unused slot parks at zero size on its neighbor's center so blobs "emerge". Concretely, the hero is one capsule. Project cards are three to five rounded boxes that bud off it. The timeline is a thin bar with small circle nodes merged at low k so they bead onto it. The terminal is a large rounded box with an `opOnion` border ring or a subtracted title-bar groove (built from smooth max, which is `-smin(-a, -b, k)`) ([IQ 2D SDFs](https://iquilezles.org/articles/distfunctions2d/)). The portrait state hands off to particles.

Springs should be semi-implicit Euler with damping ratio ζ ≈ 0.6–0.75 for Apple-like overshoot and ζ = 1 under reduced motion, with dt clamped to at most 1/30 s. Alternatively, pmndrs' `maath` `easing.damp`, which returns `false` once settled, can tell the loop when to sleep ([maath 0.10.8](https://unpkg.com/maath@0.10.8/dist/declarations/src/easing.d.ts)). Cursor gravity has two layers. The first is a domain warp that bulges the side of the pill facing the cursor, kept under about 0.3 of the half-height so the SDF stays well behaved. The second is a spring-lagged "attractor" circle merged into the `smin` chain with a large k, which grows a gooey nub that snaps back. Velocity stretch, ripples on click and a 0.96× "press" squash complete the physics. These formulas are synthesized from standard practice rather than taken from a published UI-pill source, so they need tuning by eye. Rejected alternatives are documented: the SVG goo filter blurs whatever content sits inside it and cannot light the surface ([CSS-Tricks](https://css-tricks.com/?p=195076)), and SVG displacement glass works only in Chromium for `backdrop-filter` ([kube.io](https://kube.io/blog/liquid-glass-css-svg/)). A Framer-Motion-style CSS pill (springs on width, height and radius, as in [cult-ui](https://cult-ui.com/components)) is still valuable, but as the fallback renderer.

## The code-to-portrait moment needs a stateless, scrubbable simulation

The standout moment works best as a pure function of scroll progress. Each particle computes `mix(start, target, ease(localT))` plus curl-noise displacement windowed by `sin(π·e)`, so the noise vanishes at both endpoints. That makes **scrubbing backwards exact**, which a velocity integrator cannot do. Maxime Heckel's FBO particle pattern is stateless in exactly this way: positions are computed from time and initial textures, with shape morphs done by `mix` between data textures. His demo runs 16,384 particles with "little to no frame drop" and exceeds 1M on an M1 MacBook Pro ([Maxime Heckel](https://blog.maximeheckel.com/posts/the-magical-world-of-particles-with-react-three-fiber-and-shaders/)). A per-particle delay derived from a seed and from distance to the pill center gives a staggered burst. Collapse runs progress back down, or reuses the function with a new curl seed so forward scrolling never looks like a literal rewind. A small stateful offset buffer, damped toward zero, can add cursor repulsion and "breathing" during the hold without breaking reversibility.

Targets come from the portrait, sampled once at build time. A Node script draws the photo and an alpha matte, importance-samples pixels weighted by `alpha × luminance` (light glyphs on black), relaxes them with Poisson-disk or Lloyd iterations for a blue-noise look, and ships a quantized binary buffer. The research notes put 40k particles at **about 1.1 MB raw**, and much less once gzipped and quantized to Uint16. This combines the image-pixel approach of Bruno Imbrizi's Codrops "Interactive Particles" ([GitHub](https://github.com/designagencyuk/interactive-particles)) with Dominik Fojcik's GPGPU sim ([Codrops](https://tympanus.net/codrops/2024/12/19/crafting-a-dreamy-particle-effect-with-three-js-and-gpgpu/)). No published tutorial does both. Start positions are sampled across the pill's stadium area and aligned pixel-exactly with the DOM pill through an orthographic projection. The SDF canvas fades out at about 2% progress while particles overlap it exactly, so the dissolve reads as one object changing state. Sorting starts and targets along the same axis before pairing reduces crossing paths.

The glyphs are what make this personal, and the research found **no existing demo that uses source-code tokens as particles**. A build-time plugin tokenizes the repository's own `src/**` and keeps the most frequent 256–1024 tokens (`const`, `=>`, `smin`, `uRect`). It rasterizes them into an MSDF or plain SDF atlas (2048², with a JSON file of UV rectangles), so the portrait is literally assembled from the code that renders it. Rendering must be a custom instanced-quad system with per-instance UV rectangle, aspect, size and color. **troika and drei `<Text>` break under WebGPURenderer**: one forum report shows a white square, and in Utsubo's test the render pass crashed on WebGPU and drew nothing on the WebGL2 backend ([three.js forum](https://discourse.threejs.org/t/troika-three-text-and-webgpu/55737); [Utsubo](https://www.utsubo.com/blog/webgpu-threejs-migration-guide)). The closest published precedent is Codrops' January 2026 "WebGPU Gommage" effect, which dissolves MSDF text into particles in TSL ([Codrops](https://tympanus.net/codrops/2026/01/28/webgpu-gommage-effect-dissolving-msdf-text-into-dust-and-petals-with-three-js-tsl/)). In flight, glyphs should be large and legible enough to read as code. On assembly they shrink, scaled by target luminance (0.3–1.0) and tinted along the violet-cyan ramp. Below about 6 px they blur into dots, which helps the face read.

On the WebGPU-versus-WebGL2 question, the evidence favors TSL for this effect specifically. three.js `WebGPURenderer` falls back to a WebGL2 backend that **emulates `renderer.compute()` with transform feedback**. One TSL codebase therefore covers both, provided it avoids workgroup shared memory, storage textures and indirect draws ([Utsubo migration guide](https://www.utsubo.com/blog/webgpu-threejs-migration-guide); [WebGLBackend source](https://app.unpkg.com/three@0.181.2/files/src/renderers/webgl-fallback/WebGLBackend.js)). The official `webgpu_compute_particles` example runs 200,000 particles with `instancedArray` buffers and `Fn().compute()` kernels ([three.js](https://github.com/mrdoob/three.js/blob/dev/examples/webgpu_compute_particles.html)). WebGPU now ships in Chrome, Edge, Safari 26 and Firefox on Windows and Apple Silicon macOS, at **about 87% global support** as of August 2026 caniuse data, though Firefox on Linux and Android is still not in stable ([web.dev](https://web.dev/blog/webgpu-supported-major-browsers); [Utsubo](https://www.utsubo.com/blog/webgpu-threejs-migration-guide)). There are real caveats. The three.js manual still labels WebGPURenderer experimental. r182 regressed against WebGL r170 in some scenes, with a maintainer saying the fixes landed toward r183 ([three.js forum](https://discourse.threejs.org/t/webgpu-significant-performance-drop-and-shadow-quality-regression-in-r182-vs-webgl-r170/89322)). Sources also conflict on how complete the compute fallback is, so every kernel must be tested with `forceWebGL: true`. Because the particle math is analytic, it can even run in the vertex stage, which makes the "compute" requirement optional. That is the safety valve if the fallback misbehaves.

## One persistent canvas, one RAF, and HTML that never waits for it

The stack recommendation is **Next.js 16 App Router with static generation** for `/` and `/work/[slug]`. A client-only island canvas mounts once in `app/layout.tsx` and persists across routes, because a canvas per route reloads assets and produces "Context Lost" errors ([three.js forum](https://discourse.threejs.org/t/context-lost-when-i-route-to-another-page-in-react-three-fiber/61736)). Current versions as of 2026-11-04 are `next` 16.4.5, `react` 19.3.1, `three` 0.187.0, `lenis` 1.3.27 and `gsap` 3.15.1 (npm registry, read first-hand in the research). The island itself needs no framework. It is one quad and a few hundred lines of WebGL2 or OGL, which keeps it out of the heavy chunk so it can appear early. Only the particle section pulls in `three/webgpu`. R3F 9.8.x is a reasonable host if Sahaj wants React co-location: it supports WebGPU through an async `gl` factory ([Utsubo](https://www.utsubo.com/blog/webgpu-threejs-migration-guide)) and peers `react >=19 <19.4`. R3F v10 is still alpha, though, and a single custom loop is easier to reason about without it. Astro 7 with a `transition:persist` island ([Astro docs](https://docs.astro.build/en/guides/view-transitions/)) is the credible alternative if case studies become long MDX. Avoid `@theatre/r3f`: it peers fiber v8 and has not shipped since May 2024.

Scroll must stay native. Lenis smooths the real document scroll, so sticky positioning, anchors, find-in-page and keyboard scrolling keep working. Lenis also **disables smoothing by default under `prefers-reduced-motion`** ([Lenis](https://github.com/darkroomengineering/lenis)). GSAP ScrollTrigger reads that scroll, and GSAP, including all former Club plugins such as SplitText and MorphSVG, is now free for commercial use ([GSAP Standard License](https://gsap.com/standard-license)). Everything runs on one GSAP ticker that calls `lenis.raf`, steps the island springs, and renders whichever canvases are active. Scrubbed ScrollTriggers write normalized progress into a plain mutable store, never React state, to protect INP. Rects are cached on resize and ScrollTrigger refresh, with the scroll offset added per frame, so the loop never forces layout. Avoid drei `ScrollControls`, which builds a virtual scroll container that conflicts with real document scroll, anchor links, find-in-page and Lenis ([drei View docs](https://drei.docs.pmnd.rs/portals/view)). NN/g found **every participant disoriented on a fully scrolljacked page**, and that scrolljacking was tolerated best when few scroll interactions were needed to see change ([NN/g](https://www.nngroup.com/articles/scrolljacking-101/)). So each morph should complete within a short scroll distance and stay interruptible. Same-document View Transitions are Baseline and suit DOM route changes ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/view-transitions)). Cross-document transitions still lack Firefox support and should not be relied on.

Accessibility follows from the architecture. Canvases are `aria-hidden` with `pointer-events:none`, and all text, links and buttons are semantic DOM in document order with visible focus rings and a skip link. Cursor gravity needs a touch equivalent (tap ripples, drag-to-stretch) and must turn off under reduced motion. Touch handling must also suppress iOS long-press menus and text-selection highlights, which commenters reported on Bruno Simon's canvas ([Hacker News](https://news.ycombinator.com/item?id=46206531)). A visible "pause motion" control supports WCAG 2.2.2 Pause, Stop, Hide for motion lasting longer than 5 seconds. Tiering combines `detect-gpu` at boot (tier 0 means no WebGL, a blocklisted GPU, or under 15 fps) ([detect-gpu](https://github.com/pmndrs/detect-gpu)) with a runtime FPS monitor that cuts the visible particle count in 25% steps, which is smoother than DPR changes for a fill-bound glyph effect. Note that `detect-gpu` was last published in February 2025, so new GPUs may be missing from its tiers. A `webglcontextlost` handler swaps in the CSS pill. Here the brand's second palette earns its keep: the **professional navy-and-serif theme should double as "Plain view"**. It is auto-enabled by reduced motion, Save-Data, tier 0 or a failed init, and offered as a persistent toggle. The CSS pill renders the same states with the same URLs, so a recruiter on a locked-down work laptop gets a fully designed site rather than a broken one.

That Windows laptop is also the hardware FLOAT's own users have.

## Recruiters give the first screen seconds, so the wow must cost zero

The hiring evidence is thin but consistent. The only eye-tracking data covers resumes: **7.4 seconds** for an initial screen in Ladders' 2018 study, which critics say measures a keep-reading decision, not a review ([HR Dive](https://www.hrdive.com/news/eye-tracking-study-shows-recruiters-look-at-resumes-for-7-seconds/); [ERE](https://www.ere.net/articles/is-the-6-second-resume-scan-a-myth)). A small 2021 survey of 60+ hiring managers found most would look at a candidate's website, but **51% said not having one would not lower a candidate's chances**. Reviewers form their impression from the resume first, and "a bad design can make you look incompetent" ([Profy.dev](https://dev.to/profydev/this-survey-among-60-hiring-managers-reveals-don-t-waste-your-time-on-a-react-portfolio-website-17ge)). Engineering reviewers, more than recruiters, open portfolio sites, usually with the resume already in hand and rarely for more than a couple of minutes ([DEV comment](https://dev.to/j3ffjessie/comment/2cfch)). The site's job is to verify and deepen the resume. The first viewport, before any animation completes, must therefore carry his name, role, one line of positioning, two or three flagship projects with one-line outcomes, and Resume (a stable `/resume.pdf`), GitHub and email links. A hiring manager writing on HackerNoon calls this "a resume with personality" ([HackerNoon](https://hackernoon.com/faqs-for-a-software-engineering-hiring-manager-part-3-of-5-portfolios-and-githubs)).

Bruno Simon's December 2025 relaunch is the cautionary tale. On Hacker News (777 points), commenters said "it takes a minute" to load, closed the tab before seeing anything, asked for a progress indicator, and reported near-100% CPU on an M3, iOS stutter and a Firefox crash. They called it "very impressive as an art project, but terrible as an actual home page" ([Hacker News](https://news.ycombinator.com/item?id=46206531)). His first portfolio still "boost[ed] my career in crazy ways" ([Mux](https://www.mux.com/blog/3d-web-development-and-beyond-a-chat-with-bruno-simon)), but in creative-dev freelancing, not SWE hiring. One DEV commenter reported rejecting candidates for over-engineered portfolios ([jonrandy](https://dev.to/jonrandy/comment/24bp6)). The resolution is to make the effect self-evidently cheap, fast and optional. Then it reads as performance engineering, the same skill FLOAT demands. The particle portrait should sit mid-page as a reward, never as an intro gate, with a skip affordance and a remembered preference.

Each project page should follow a problem, constraints, architecture, two or three hard decisions with trade-offs, metrics, my role, demo video, and links structure, with real READMEs behind the links ([HackerNoon](https://hackernoon.com/faqs-for-a-software-engineering-hiring-manager-part-3-of-5-portfolios-and-githubs); [techinterview.org](https://www.techinterview.org/post/3233474610/side-projects-open-source-engineering-resume/)). **FLOAT and PIE lead**, because Rust/Tauri and C++-under-React-Native with offline PDFium are strong systems signals for a young developer. Both need measured numbers (RAM and CPU footprint, binary size, startup time, downloads) and 30–90 second screen recordings, since neither runs in a browser, plus GitHub Releases for verifiability. FLOAT deserves a live in-page demo: the site's island can literally re-enact FLOAT's notification states. **HARIKA's "AI OS" label invites skepticism**, so it needs a precise scope (agent shell versus kernel), a diagram, real repo activity and a demo, or it reads as hype. VERITY should show its evaluation method, accuracy, failure handling and data-privacy posture, and say plainly whether it ran on real or synthetic data. Reviewers of AI projects want to know what is engineered versus model-provided, and invented metrics are worse than an honest "not yet measured". MotherTongue Books must be labeled as a Meta hackathon project with team size, Sahaj's specific agents or pipeline ownership, any placement, and Devpost and repo links, following MLH's advice to pin hackathon repos so reviewers can confirm authorship ([MLH](https://blog.mlh.com/how-to-put-your-hackathon-project-on-your-resume-11-21-2022)). Web projects belong in a compact "also built" strip rather than full case studies, because depth on three or four projects beats breadth.

## Ship plain view first and the particle portrait last

The build order should de-risk the hiring value first and the spectacle last, so that every intermediate state is deployable.

| Phase | Deliverable | Exit criterion |
|---|---|---|
| 1. Content and plain view | SSG Next.js site in the navy/serif theme: hero, five case studies, `/resume.pdf`, OG images, JSON-LD, analytics | Lighthouse mobile ≥ 90; all content readable with JS off; case studies drafted with real metrics |
| 2. CSS island | Spring-animated DOM pill morphing between section states via slot elements (the permanent fallback) | Keyboard and reduced-motion parity with Framer's component |

| 5. Token pipeline | Build plugin that tokenizes `src/**`, MSDF atlas, blue-noise portrait sampler emitting binary buffers | Deterministic build artifacts < ~1.5 MB total |
| 6. Particle moment | Lazy `three/webgpu` + TSL scene, analytic scrubbable path, pixel-exact pill handoff, tiered counts | Passes on `forceWebGL: true`, a mid Android phone and Safari; static/video fallback at tier 0 |
| 7. Hardening and launch | Context-loss handling, pause toggle, field CWV via Speed Insights, Codrops-style making-of post, public repo | Field p75 LCP ≤ 2.5 s and INP ≤ 200 ms |

The risks are concrete. Phone fill-rate cost is the largest, which is why the counts are tiered, the work is lazy-loaded and a video fallback exists. WebGPURenderer's experimental status and version churn (r181 through r186 changed or deprecated APIs ([Utsubo](https://www.utsubo.com/blog/webgpu-threejs-migration-guide))) argue for pinning `three` and keeping the island on raw WebGL2. The DOM-to-SDF sync has no canonical library, so drift between HTML and shader is a bug class Sahaj will own. Visual confusion with Apple Liquid Glass is avoided by the matte-black material. Scope creep is the quiet killer, and phases 1–3 alone already form a distinctive, hireable site. Several technique sources (Codrops articles, IQ's Shadertoys) were seen only through summaries, so the shader snippets need prototyping before they are trusted. Publishing the source openly makes the token-portrait honest, since viewers can check that the glyphs really come from the repo, and it follows the open-source credibility pattern that worked for Bruno Simon.

## Conclusion

The idea's power comes from its recursion more than its visuals. The site's island is a working sibling of FLOAT, and the portrait is assembled from the code that draws it. Together they turn the portfolio from a container of evidence into evidence itself. That only lands if the engineering choices are as legible as the effect. That means a 2D SDF chosen over raymarching for a stated cost reason, an analytic particle path chosen for reversibility, HTML-first rendering chosen for recruiters, and a plain view that is a designed theme rather than an error state. Those choices are what a hiring manager will probe in an interview, so they should be written up in a making-of post as deliberately as they are built.

The less obvious implication is that the professional navy/serif option is not a compromise. It is the strongest hiring asset in the plan. It guarantees that the 7-second screen, the locked-down corporate laptop and the reduced-motion user all get a complete site. That frees the violet-cyan liquid mode to be as ambitious as Sahaj wants without carrying the hiring risk.
